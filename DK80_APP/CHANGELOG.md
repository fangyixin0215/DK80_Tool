## [1.3.3] - 2026-10-19

### 修复（固件）：O3/NH3 永远收不到数据的根因——睡眠唤醒把 UART0 波特率改回 115200

- **根因**：气体传感器使能后 UART0 归传感器（9600），但 SDK 睡眠唤醒钩子
  `user_entry_after_sleep_imp()` 每次唤醒都把 UART0 重配回 115200（原日志口），
  传感器 9600 上传帧全部被错波特率采样成乱码，帧同步永不成立——表现为 APP 日志
  没有任何 `o3 raw` 行、气体传感器永远"未连接"、读数恒为 0/初始值
- **修复**：`o3_uart_init` 导出为 `dk80_o3_uart_init()`，唤醒钩子在
  `DK80_O3_SENSOR_RUNTIME_ENABLE=1` 时改调它重新切回 9600 + PA0 上拉；
  唤醒/入睡的 `'w'`/`'s'` 调试字符同步屏蔽（9600 下会打进传感器 RX 形成未知命令）

### 新增：4G / 蓝牙信号强度展示

- **固件**：`AT+CSQ` 结果解析缓存（`dk80_net_get_csq()`，rssi 0~31），联网配置时
  读一次 + 在线后每 60s 刷新；CHAR1 状态快照 **byte14** 上报（0xFF=未知），
  App 侧换算 dBm = -113 + 2×rssi
- **APP**：`DeviceStatus` 新增 `csq` 字段；`BleManager` 握手就绪后每 3s
  `readRemoteRssi()` 轮询蓝牙信号（断连自动停止/复位）
- **UI**："气体检测类型"开关从设备身份移至**运行状态**栏（与传感器状态同组）；
  设备身份新增 **4G 信号**（CSQ→dBm）与**蓝牙信号**（RSSI dBm）两行

### 修复（固件）：CSQ 在 SIM 异常时永远执行不到

- `AT+CSQ` 查询原来排在 `AT+CPIN?` 之后，没插 SIM 时 CPIN 失败直接 return，
  CSQ 永远轮不到——旧固件 APP 上 4G 信号恒显示 -113 dBm 的假数据；
  已把 CSQ 挪到 CPIN 之前（CSQ 不依赖 SIM，无卡也能测到信号强度）

### 新增（固件）：气体口原始字节诊断

- UART0 RX 中断累计原始字节数并留存上电后前 32 字节，每 10s 输出
  `gas uart0 rx=N dump=...`：
  **rx=0** = 传感器一个字节都没发（接线/供电/模组问题）；
  **rx 涨但全是乱码** = 波特率不匹配。用于定位"同一块板 NH3 有数据、O3 无数据"：
  日志可区分是 O3 模组没发字节，还是发了但内容不对

### 优化（APP）：信号强度改成手机信号格样式

- 4G / 蓝牙信号行改为 **信号格图标 + dBm 文本**，4 档分格口径对齐安卓手机习惯
  （4G：≥-73 满格，≥-85 三格，≥-95 两格，≥-105 一格；蓝牙按 RSSI 同档）

## [1.3.1] - 2026-10-19

### 修复（固件）：NH3/O3 浓度解析差一字节，读数虚高百倍

- **根因**：浓度实际在帧的 **byte4/byte5**，旧实现读 byte5/byte6——byte6 是恒定的
  满量程高位 0x27（0x270F=9999），导致显示值低字节永远是 0x27（如 10.63=0x0427、
  174.47=0x4427），真实 0~4 ppm 被放大百倍。校准依据：DK80_260326 参考项目
  `gas_data_handle()` 取 `uart1_data[i+4]<<8|uart1_data[i+5]` + 规格书示例帧
  `FF 17 04 00 00 25 27 0F 25` 自洽验证（浓度 0x0025=0.37ppm，满量程 0x270F=9999）。
  规格书表头列错位，示例帧与参考代码为准
- 附带：加入参考项目同款的**正向尖峰抑制**（1s 内跳变 >100 视为干扰帧保持旧值），
  原始帧日志保留，APP 日志页可核对 `o3 raw` 字节

## [1.3.2] - 2026-10-19

### 修正：O3 浓度单位按参考项目实测标定 + 满量程健全性校验

与 DK80_260326 参考项目（同事代码）逐点核对结果：帧解析（byte4/5、校验、
尖峰抑制）完全一致，差异两处已对齐——

- **O3 单位换算**：参考项目 HT16C23A_pixel.c 注释"臭氧PPM=读到的值/100
  （20260530确定）"——O3 模组原始值同为 0.01ppm 单位（GB01 规格书标 ppb，
  以实测为准）。固件屏显与 APP 传感器卡片均改为 0.01ppm 直显（XX.XX ppm），
  原 ppb 显示取消
- **满量程校验**：采纳参考项目 process_gas_frame 的健全性校验，
  校验和通过后再要求 byte6/7 == 0x270F（9999），挡掉同校验和异常帧

## [1.3.0] - 2026-10-19

### 新增：气体检测类型运行时切换（方案 B）

两款传感器模组（GB08-NH3 / GB01-O3）帧格式逐字节相同、协议无 ID 查询命令，
无法从 UART 数据自动识别类型，改为运行时手动切换、断电保存：

- **固件**：新增 BLE 命令 `GAS:0`（NH3 氨气）/ `GAS:1`（O3 臭氧），应答 `GAS:ACK,n`；
  切换后即时更新 LCD 文字标（氨气/臭氧）与数值换算（NH3 0.01ppm 直显 / O3 ppb÷10），
  并立即落盘，重启保持。保存结构 `dk80_mode_save_t` 追加 `gas_type` 字段，
  MAGIC 升版 0x3160AC79（旧记录自动作废、按 `DK80_GAS_TYPE_DEFAULT` 重建）。
  `INFO?` 与握手 `HS:ACK` 的 `GAS=` 字段改为返回运行时类型
- **App**：工况页「气体检测类型」由纯文本改为 **NH₃ 氨气 / O₃ 臭氧 双选开关**
  （FilterChip，未连接时禁用），点击即发 `GAS:` 命令并乐观更新本地显示

## [1.2.3] - 2026-10-19

### 修复（固件）

- **LCD 时间/冒号偶发冻住**：根因与 v1.2.1 遥控卡顿同源——4G AT 引擎阻塞等待期间
  主循环停摆。`ble_stack_schedule` 只派发 os_timer（RTC 影子照走），但 `dk80_lcd_task`
  是主循环任务，AT 长阻塞（最长 HTTP GET 60s）期间屏驱不被调用，时间显示整个冻结、
  结束后跳变。现 `at_wait_response` 等待循环内每 ~20ms 代调一次 `dk80_display_task()`
  （该函数内部自带 blink/refresh 节流，重复调用安全），AT 阻塞期间 LCD 保持正常刷新

## [1.2.2] - 2026-10-19

### 说明（NH3 数值离谱问题排查结论）

- **解析无误**：逐字节核对 GB08-NH3-99.99 规格书（深圳家邦）表4/表8，
  浓度 = (Byte5×256+Byte6)/100 PPM、校验 = 取反(Byte1..Byte7)+1，与固件实现完全一致
- 离谱值（174ppm → 10ppm 一路下降）是**电化学传感器未老化**的典型表现：
  规格书要求使用前老化 ≥48 小时、预热 ≤3 分钟，模组无校准命令，零漂靠老化+洁净空气自然归零
- 净化器内部等离子杀菌产生的强氧化性气体会干扰电化学 NH3 电极，装机位置需远离等离子模块

### 变更

- 固件：GB08 模组每 5 秒输出一条原始帧 hex 日志（`o3 raw ...`），APP 日志页可直接核对传感器原始字节
- App：传感器卡片数值字号 24sp→20sp，修复 "174.47" 6 位数值换行断字

## [1.2.1] - 2026-10-19

### 修复（固件）

- **IMEI/ICCID/IMSI 空白**：`ec800k_read_id_info()` 原在 `AT+CPIN?` 之后调用，
  SIM 异常（实测 ME ERROR 14）时 CPIN? 失败提前返回，身份信息永远读不到。
  现移到 CPIN 检查之前：IMEI(AT+GSN)/ICCID(AT+QCCID) 不依赖 SIM PIN 即可取到；
  `net_extract_id()` 没提取到数字时保留旧值，重试不清空已缓存身份
- **遥控按键"按了没反应、随后爆发响应"**：AT 引擎 `at_wait_response()` 阻塞轮询期间
  主循环停摆，手机 GATT 写请求积压。等待循环内每 1ms 让出一次 `ble_stack_schedule()`，
  阻塞期间蓝牙照常处理写请求

### 变更（Android App）

- 工况页文案：「UV 杀菌」→「**等离子杀菌**」；**去掉「臭氧发生器」行**（硬件无此部件）；
  「气体类型」→「**气体检测类型**」
- 修复日志页切走再回来后「开启日志/停止」按钮状态丢失：开关状态提升到 BleManager
  （`logStreamOn` StateFlow），且断连重连握手成功后自动补发 `LOG:1` 恢复日志流

## [1.2.0] - 2026-10-19

### 变更（固件，UART0 划归气体传感器）

- `DK80_O3_SENSOR_RUNTIME_ENABLE = 1`：UART0（PA0=RX/PA1=TX @9600）正式用于 GB01-O3 / GB08-NH3 气体传感器
  （主动上传帧 `FF 17 ...` 解析此前已就绪，本次正式启用）
- PA0 RX 使能内部上拉：传感器未接/断线时 RX 保持空闲高电平，消除悬空中断风暴（2026-10-15 实测问题）
- `dk80_ble_log.c` 在传感器使能时静默 UART0 TX：日志只进 BLE 环形缓冲，不再往传感器口发垃圾，
  量产日志完全走 BLE 调试通道（APP 日志页查看/导出）
- 新增 `dk80_gas_sensor_online()`：5s 内收到过合法帧视为在线
- CHAR1 状态快照 byte[13] bit0 上报气体传感器在线位（原 reserved）

### 变更（Android App）

- 工况页**去掉 PM10**（硬件无此数据），传感器卡片改为 气体/温度/湿度 一行三列
- 气体浓度按类型换算显示：O3 显示 ppb 原值，NH3 显示 ppm（原始值 ÷100，保留两位小数）
- 运行状态新增 **NH₃/O₃ 传感器连接状态**（绿=已连接 / 红=未连接，来自 CHAR1 byte[13]）
- `DeviceStatus` 字段调整：`ozonePpb/pm10` → `gasRaw` + `gasOnline`

## [1.1.0] - 2026-10-19

### 修复（固件，连上即断 / 先开连不上）

- **根因**：`dk80_gatt_service.c` 连接状态（`dk80_connected` / CCC 使能位）只置位、断开从不清理，
  主循环每 3s 对失效连接 `gatt_notification` 触发 BLE 栈断言整机重启（串口日志表现为 `\0 freqchip` 周期性重现）；
  重启窗口期广播消失导致"设备先开根本连不上"
- 新增 `dk80_gatt_on_disconnect()`：断开时清连接标记 / CCC / 挂起标志，挂钩 `GAP_EVT_DISCONNECT`
- `dk80_gatt_notify_status()` 增加 `dk80_connected` 守卫，链路失效绝不发送 notify
- CCC 写处理不再在协议栈消息上下文里同步重入 `gatt_notification`，
  首次状态推送改由主循环 deferred 发送（置 `s_status_pending` 标志）
- 日志流限流：主循环每轮最多发 4 行日志 notify，避免日志洪峰饿死 BLE 调度与 4G AT 引擎

### 变更（Android App）

- 断连自动重连：异常断开 / 连接失败后 1.2s 自动回到扫描持续重连；扫描 10s 超时自动续扫，
  直到用户主动点"断开"（`userClosed` 标志区分主动/被动断开）
- 遥控器页重新设计：大圆形电源主按钮 + 全按键 Material 图标 + 按功能分组配色
  （风速蓝 / 循环青 / 定时紫 / 童锁琥珀 / 时分校正灰阶 / 确认绿 / 取消红），分区标题引导

## [1.0.0] - 2026-10-17

### 新增（固件 BLE 调试通道）

- 新增 **DK80 自定义 GATT 服务**（UUID `0xFFD0`），含三个特征：
  - CHAR1 (`0xFFD1`)：16 字节二进制状态快照（Read / Notify）
  - CHAR2 (`0xFFD2`)：文本命令通道（Write）
  - CHAR3 (`0xFFD3`)：调试响应 + 日志流（Notify，变长文本行）
- 新增 **握手协议**：`HS:REQ` → `HS:ACK FW=.. HW=.. BUILD=.. SN=<MAC> GAS=..`
- 新增 **按键遥控**：`KEY:<0-15>` 复用红外码值表（`dk80_mode_ir_cmd`）
- 新增 **设备信息查询**：`INFO?` 返回 IMEI / ICCID / IMSI / MAC / FW / HW / BUILD / GAS
- 新增 **日志流**：`LOG:<0|1>` 开关，`co_log` 经环形缓冲按行 Notify 到 App
- 新增 **状态查询**：`STA?` 立即推送一次 CHAR1 状态
- 新增 **OTA 握手**：`OTA:START` → `OTA:READY`，App 切到 SDK `ble_ota` 服务
- 新增 `dk80_ble_log.c/h`：挂钩 `fputc_imp`，不影响 UART0，2KB 环形缓冲
- `dk80_module_net.c`：联网建立时缓存 IMEI / ICCID / IMSI 并暴露 getter
- `dk80_board.h`：定义 `DK80_FW_VER_STRING` / `DK80_HW_VER_STRING` / `DK80_GAS_TYPE_DEFAULT`
- Keil 工程加入 `dk80_ble_log.c` / `ota_service.c` / `ota.c`
- **量产宏控制**：`DK80_BLE_DEBUG_EN`、`DK80_BLE_LOG_EN`

### 新增（Android App）

- 工程骨架：Kotlin + Jetpack Compose + Material3，minSdk 26 / targetSdk 34
- BLE 核心 `BleManager`：扫描过滤 DK80 服务 UUID → 连接 → MTU 247 → 开 CHAR1/CHAR3 通知 → 握手 → Ready；串行写队列 + MTU-3 分片
- **遥控页**：圆形按键网格，键值与红外码一一对应（电源/童锁/风±/定时/循环/预约/时±/分±/时间/复位）
- **工况页**：实时传感器（PM2.5 / PM10 / NH₃或O₃ / 温湿度）+ 风扇/UV/臭氧，设备身份信息卡
- **日志页**：实时日志流开关、清空、一键导出 txt 并系统分享
- **OTA 页**：选择固件 bin → 按 MTU 分片写入 ble_ota RX 特征，带进度条
- 顶部连接状态栏（状态/设备名/扫描/断开）
- Android 12+ 蓝牙权限处理、FileProvider 导出

### 编译验证

- 固件 Keil 编译：**0 Error**（2 个预存 scatter 警告与本次无关）

### 已知待办

- OTA 分片写入为通用实现，若固件 `ota_service` 要求特定包头/校验，需在 `BleManager.sendOtaData` 中按协议封装
- 未配置 App 图标（暂用系统默认图标）
- 未配置签名（release 构建需自行配置 keystore）
